When enabled, flight & meteo records older than the threshold are automatically purged once per day. GPS Quality, Approach History and the GPS Episode Log are never auto-purged.
Archive before purge: every flight & meteo purge (automatic and manual) first copies the observations and their flights to a monthly archive file (modes_meteo_archive_YYYY-MM.db, see below), and the daily retention purges of approach_series, departure_series and departure_profiles do the same. Nothing is deleted unless the copy succeeded and was checked.
Archive Files & Snapshots
Folder: —
FileSizeObservationsFirstLast
—
Monthly archive files hold the purged observations (all columns, same ids) with their flights, and the archived approach series and departure profiles. A snapshot is a compact copy of the whole running database (all tables) at that moment, e.g. for analysis on another computer. Both are ordinary SQLite files; tools/archive_query.py combines the archive files with the running database. Compressed (gzip) makes the snapshot about half the size (.db.gz, open with gunzip or 7-Zip) — quicker to download. Download saves a file in your browser; Delete is offered for snapshots only — the monthly archive files are the only copy of the purged data.

Local JSON Feed (localhost) An aircraft list for another program on this same machine (e.g. modes_logger, adsb_radar): each connection to 127.0.0.1 on the port below gets the newest list of the chosen receiver(s), in the Radarcape list's form, then the connection closes. Only from this machine — never from the internet.
Status
—
Off by default: then nothing listens on the port. List: the main receiver's Radarcape list as received (the default); All receivers (merged) — MODE-S Wind's own aircraft (every receiver, each aircraft once, heard within 60 s, with the selected altitude) on top of the main receiver's list, which keeps its own entries — also of the aircraft MODE-S Wind leaves out, such as helicopters. Note: the aircraft MODE-S Wind filters out (the WAM ground stations T40…, the OH-H helicopters — BLOCKED_ICAO_PREFIXES / BLOCKED_REG_PREFIXES) are in the merged list only when the main receiver (RX-01) hears them; heard only by another receiver, they are missing; or another receiver's own list (readsb's aircraft.json, polled every 2 s only while chosen). A list older than 10 s (the receiver or its connection down) is sent as an empty list [], so nothing stale is logged. The list is not stored. The port (31009) can be changed with JSON_FEED_PORT in config_local.py.
Local Beast Feed (localhost) Every reply the receivers hear — with more receivers merged: the same reply once, in time order, about 0.8 s late — as a continuous Beast stream for another program on this same machine (readsb / dump1090 net-connector, pyModeS …). Only from this machine — never from the internet. Not for multilateration: the time stamps of different receivers are only lined up. Unfiltered: unlike MODE-S Wind's own pages and the JSON feed's merged list, the Beast stream is not filtered — the WAM ground stations (T40…) and the OH-H helicopters (BLOCKED_ICAO_PREFIXES / BLOCKED_REG_PREFIXES) are in it from every receiver.
Status
—
Off by default: then nothing listens on the port. Each frame: 0x1a, type 2 / 3 (Mode S short / long), 6-byte time stamp, signal byte (of the first receiver that heard it), payload. A program more than 2 MB behind is disconnected. Nothing is stored. The port (31005) can be changed with BEAST_FEED_PORT in config_local.py.
